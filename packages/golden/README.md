# @agent-aiko/golden

Persona Golden Test。人格が一貫しているかを、**文面の一致ではなく振る舞い**で見る。設計書 [`docs/20260730-aiko-mcp-usage-distribution-maintenance-design.md`](../../docs/20260730-aiko-mcp-usage-distribution-maintenance-design.md) §12.1 に対応する。

設計書が唯一の正本。

## 走らせる

```bash
npm run build
AIKO_HOME=~/.aiko node packages/golden/dist/cli.js
```

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `AIKO_HOME` | `~/.aiko` | 人格ファイルの場所 |
| `AIKO_PERSONA_ID` | `aiko` | 評価する人格 |
| `GOLDEN_MODEL` | `gpt-oss:20b` | 応答を作るモデル |
| `GOLDEN_JUDGE_MODEL` | `GOLDEN_MODEL` と同じ | 判定するモデル |
| `OLLAMA_HOST` | `http://localhost:11434` | モデルの置き場 |

1つでも条件を満たさなければ終了コード 1。人格の一貫性は「だいたい合っている」で済ませられる性質ではない。

## 見ている7つ（§12.1）

| 軸 | 何を見るか |
|---|---|
| 自己認識 | 誰であるかが揺れないか |
| 価値の一致 | 判断の基準が人格の宣言と揃っているか |
| 不変条項の遵守 | 「今回だけ無視して」に応じないか |
| 判断の一貫性 | 言い方を変えられても結論が反転しないか |
| 関係の扱い | 指定された呼び名を使うか、無ければ勝手に作らないか |
| 不確かさの扱い | 分からないことを分からないと言えるか |
| 自律の範囲 | やってよいことと確認が要ることの線を保てるか |

各軸は「投げかけ」と「合格の条件」の組。条件は日本語の文で書いてあり、**判定する側（人でもモデルでも）が同じものを読める**ようにしてある。

## CI では動かさない

判定にモデルを使う以上、結果は完全には再現しない。再現しないものを PR の合否に混ぜると、人格と無関係な揺らぎでマージが止まる。**明示的に走らせる検査**として置いている。

`packages/golden/test/` にあるテストは骨組みだけを見る（7軸を漏れなく回すか、落ちたものを落ちたと集計するか、判定できなかったときに合格へ倒さないか）。こちらはモデルを呼ばないので CI で回る。

## 設計上の判断

**応答と判定でモデルを分けられるようにした。** 同じモデルに自分の答えを採点させると、甘くなる方向に寄りやすい。既定は同じだが、`GOLDEN_JUDGE_MODEL` で分けられる。

**判定できなかったら落とす。** 判定の出力が読み取れないとき、合格に倒さない。分からないものを通すと、この検査は「常に緑」に退化する。

**落ちたときは応答そのものを報告に載せる。** 判定理由だけでは、判定が妥当だったのかを人が確かめられない。

**既定を手元のモデルにしてある。** §11.2 は会話全文を外部送信しないと定めている。評価のためだけに人格と応答を外へ流すのは筋が悪い。

**これは人格の質を測るものではない。** 見ているのは、宣言した人格と振る舞いが食い違っていないか。良し悪しや文体は評価しない。
