# HTTP / OAuth 接続の安全性確認

確認日: 2026-10-23。対象は `packages/mcp-server` のローカルHTTP・OAuth接続。
これは実装者によるコード確認と自動テストの記録であり、外部公開の受入完了を意味しない。

## 確認した動作

- 通常の引数なし起動はstdio。HTTPは `http` または `oauth` コマンドを指定した場合だけ待ち受ける。
- 待受アドレスは127.0.0.1固定。HostとOriginの不一致は認証・セッション作成より前に拒否する。
- `http` は共有トークン必須。`oauth` は署名・issuer・audience・期限・発行時刻・token type・scope・所有者・client_idを検証する。認証方式の混在やフォールバックはしない。
- OAuth所有者は1人に限定する。別の認証主体で既存セッションIDを再利用できない。
- HTTP/OAuthコマンドは人格削除、人格保存・切り替え、話し方切り替え、ユーザー情報変更のツールを登録しない。認証済みでも直接呼び出すと拒否する。
- セッション上限32件、無操作15分、本文1 MiB。処理中リクエストは認証処理を含め32件まで、TCP接続は128件までに制限する。
- 認証処理中にクライアントが切断しても、認証処理が終わるまで処理枠を解放しない。切断済みリクエスト用のMCPサーバーを作成しない。
- MCP応答に `Cache-Control: no-store` を付ける。トークンを診断ログに出力しない。

## 回帰テスト

`packages/mcp-server/test/http.test.ts` で、不正認証、Host/Origin不一致、本文超過、セッション制限と失効、並行処理上限と切断による回避、配布バイナリの起動・終了を検証する。
配布バイナリへの認証済み接続から変更・削除を試みても、テスト用の実在する人格とuser.mdが変化しないことを確認する。

`packages/mcp-server/test/oauth.test.ts` で、テスト鍵による正常な署名と偽造・期限切れ・宛先/issuer違い・IDトークン・権限不足、Discovery、認証主体ごとのセッション照合を検証する。
`stdio.test.ts` と既存の変更操作テストで、従来のローカルstdio利用が維持されていることを検証する。

実行: `npm run typecheck`、`npm test`。HTTPテストはローカルポートの利用が必要。

## 未確認の範囲

実際のOAuth認証基盤を使うログイン・同意・PKCEコード交換、Claude.ai/ChatGPTでの接続は未確認。
発行済みOAuthトークンの即時失効を照会する仕組みは未実装。現状のJWT検証は期限・発行時刻と署名鍵を基準にするため、認証基盤側のログアウトや失効操作が直ちに反映されるとは限らない。
HTTPS公開・プロキシ設定・公開環境での負荷や攻撃への耐性も未確認で、外部公開は行っていない。

認証済みのクライアントには人格・設定の読取りを許可する。接続先クライアントへ返したデータの保管・利用はこのサーバーだけでは制御できない。
共有トークンや同一OSユーザーの権限を持つ不正なプロセスに対する隔離も、この仕組みが保証する範囲ではない。

外部利用を開始する前に、使う認証基盤・接続先・送信してよいデータを確定し、実環境での受入確認を行う必要がある。
